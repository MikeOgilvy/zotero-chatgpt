# Changelog

All notable user-facing changes will be recorded here. Versions below are **development previews**, not GitHub Releases.

## Unreleased

### Development preview `0.4.0-alpha.1`

- Fixed the **Chat / Agent mode switch** after owner feedback that the `Chat` option could not be selected and that ordinary questions still ran through the action path. Two root causes: the composer helper dropped the caller's CSS class for a text button, so the options rendered with the generic button skin and the pressed fill (`aria-pressed`) never applied; and the Chat/Agent boundary was only enforced by the presenter. The options now carry `.zchatgpt-mode-option` and show the selected mode, and the **runtime enforces the boundary**: the session service refuses any request that is not in Agent mode while carrying Agent work (a multi-pass reading batch or a non-`read` skill), and the reading coordinator refuses to create a job from a Chat request and freezes every step as Agent. A plain Chat question still reads and uses the current PDF, and complex questions are refused with a "switch to Agent" prompt rather than escalated. Both modes still share one model transport — there is no second quota system or hidden meter; the difference is that Chat creates no reading job or native task. The development add-on version moves to `0.4.0a14`.
- Renamed the project to **Zotero ChatGPT**: repository and npm `zotero-chatgpt`, display name "Zotero ChatGPT", XPI `zotero-chatgpt-<version>-dev.xpi`, addon id `{90909501-7b5b-4985-9f55-566e9890746c}`, runtime state under `zotero-chatgpt/v1/`, preferences under `extensions.zchatgpt.*`, bundle `content/zchatgpt.js`, and annotation provenance `[AI · Zotero ChatGPT]`. The development addon version moves to `0.4.0a11`. This is a **re-identity, not a cosmetic rename**: the renamed build is a different addon from earlier previews, records under the old storage directory are not read (no migration is implemented, and the old directory is left in place), and AI annotations written before the rename no longer match the new provenance string.

- Documented the **Chat Mode / Agent Mode** product architecture: Chat Mode is the first-class read-only conversational reader (automatic current-PDF context, retrieval, page/quote citations), Agent Mode adds Zotero/file actions on the same shared document context and conversation, and the currently opened PDF is treated as implicit context rather than a manually attached file. Docs only; no behavior change.
- Implemented the **Chat / Agent mode switch** as a user-visible per-chat control at the start of the composer (segmented `Chat` / `Agent`). The chosen mode is captured when a request is submitted and **frozen for that request**, so switching afterwards never re-labels an earlier turn; the next turn uses the new choice. Default is Chat.
- **Chat Mode is structurally read-only**: Agent-only skills (annotation and acquisition/diagram) are refused before any model request, document read or task is created, and the task/approval surface stays hidden. Chat Mode therefore does not require the action infrastructure at all.
- **Chat and Agent now run on two named execution paths** instead of branches of one submit. In Chat mode a natural-language request to change the library (for example "highlight this") is refused up front with a prompt to switch to Agent mode instead of being silently turned into a write, and a context large enough to need multi-pass reading is likewise refused in Chat rather than escalated. Chat mode does not initialize the action or reading infrastructure on send, on refresh, or when deleting a chat, so an ordinary chat stays an ordinary chat. Both modes still share one conversation and one document context, and the mode is frozen per request as before.
- Both modes **share one conversation, one document context, one presenter and one history**, so the same chat continues across the switch with the current PDF and prior turns intact; the mode is only routing and grants no permission (writes still require explicit approval). The unpersisted tab is **New chat** and no longer carries the article title; paper identity comes from the attachment/context system.
- Notable refactor outcomes a user can notice: the reading side is separated from the write side (Chat never imports the action layer), the model-picker offer policy and the per-request context budget now come from a single source in `core`, and dead chrome from the old sidebar editor is gone (unused paste/scale hooks, a redundant rename append, and stale workspace-editor selectors plus their CSS). The development add-on version moves to `0.4.0a13` (the Chat / Agent execution-path split in the same refactor changed the bundle bytes); the mode contract, per-request freezing and the UI switch all landed in the same 7-stage refactor.
- Adopted the MIT license for the project; the root `LICENSE` now ships inside the development XPI and `package.json` declares `"license": "MIT"`.
- Added agent/task/workspace contracts and persistent local services: workspace preferences, research profiles and SKILL.md, unified `@article`/`@chat` references, offline history/drafts, and a native task ledger with approval, undo and conflict detection.
- Added context planning and long-document handling: per-turn budget from the runtime window or the pinned catalog, focused and multi-pass reading, batch queueing, deterministic source ids and a 3 × 16 MiB local text cache, plus loaded-vs-disk SHA-256 PDF version checks.
- Added model capability/usage handling and multimodal support: catalog modalities, provider capability and rate-limit parsing, 2 MiB input images, verified 16 MiB generated images, and the explicit diagram workflow.
- Added the workspace, task, command-menu and UI-locale views, and made answer source links resolve `https://zchatgpt.invalid/source/<documentId>/<pageIndex>` against the frozen document revision. The reading instruction now tells the model to emit that reserved form.
- Added an honest elapsed-time indicator for a running request: it counts whole seconds while unsettled, freezes at the first delivered text, and stops at the settled "Answered in N s"; missing timing shows an explicit unknown instead of an invented duration, so a slow answer no longer looks like a local hang or implies upstream quota/queueing was the app's fault. Related fixes from the merged `feat/usage-batch-1` branch: Unicode/currency math renders without mangling text, `@` references search every readable Zotero library, annotation candidates stay resolvable when the model omits a comment, the current PDF is prepared when the panel opens, every pasted/dropped clipboard image is kept, and the item-pane icon was redrawn.
- Merged the independently verified `fix/audit-bugs-ui` branch, fixing user-reported defects: answers blanking after citation rendering (`structuredClone`), the presenter not re-subscribing after a runtime reconnect, one failing view stopping the others, undiscoverable copy affordances, and the composer/profile/page-range/splitter/dock dark-mode issues; it also added answer typography with one stylesheet per view, composer spacing, remaining dynamic-string localization, an honest current-context chip, and one empty chat per paper instead of stacked duplicates.
- Moved the global settings into Zotero's own Preferences window: a native pane (`Zotero ChatGPT`) registered from `startup()` and cleaned up on `shutdown()` now edits the stored UI language, chat text scale, the six answer preferences, research profiles and workflow availability through the existing workspace store (one validated snapshot or one skill revision at a time, honest store errors, no second source of truth). The pane receives JSON text functions only, exposes no credentials, paths or permissions, and a refused write re-reads the store instead of showing a state it refused. The sidebar keeps the per-chat profile choice, per-chat overrides, references and workflow authoring, and points at the Preferences window; the preference export moved with the settings and now shares one snapshot definition with the sidebar.
- Made a cited claim trace back to the article: clicking a `zchatgpt.invalid/source/<id>/<page>` citation verifies the frozen document revision first, then locates the verbatim quote the model put in the link title on that exact page and navigates with a transient highlight; an absent or unlocatable quote opens the page and says honestly that the exact passage could not be located, and clicking a citation never writes to the library. The citation instruction in `reader-policy.ts` now asks for a short verbatim quote in the link title (code/unit evidence only: no live-model run).
- The sidebar now uses Cursor-style agent tabs in the chrome: named open chats on the left, an unpersisted **New chat** tab until the first send, the close cross only on the selected tab, and `+` / history on the right. Empty `+` clicks no longer write “讨论 N” ghost chats. The dock never splits into two transcripts; other open chats are tabs only. The attach popover is a single **Attach file** row (multi-select text or image); “Choose images” and “Capture selected region” are gone. Clipboard paste continues past a throwing reader-window clipboard route, and a macOS TIFF screenshot is converted to PNG when imgITools can encode one. The native Preferences pane registers `defaultXUL: true` and the pane script’s `mount` cannot abort Zotero’s pane switch.
- First open of a paper puts the article title on the unbound tab as soon as the composer exists, before a conversation is restored or created; pressing `+` beside an already-open named chat is still the New chat copy, and neither path writes an empty record.
- Reworked the sidebar chrome around the owner's reading flow: the three-dot chat menu is gone, with Rename chat on the chat title itself and Account usage inside the model picker; the new-chat and history buttons moved to the right; references and skills are separate entry points; history rows delete directly with no confirmation dialog; and every user-facing "workflow" now reads "skill" while the stored schema, ids and skill names are unchanged.
- The sidebar now shows what the reader read about this paper — title, authors and whichever of item type, journal, year, volume, issue, pages, publisher, DOI, ISBN/ISSN, language, editors, tags and abstract Zotero actually declared — and states the local read that happened ("Read all N pages locally", or the honest partial count). The field list, its caps and the "absent stays absent" rule are shared with the compact bibliographic block in the reading request, so the card and the model describe one paper the same way, and a request carries every field the reader read instead of a four-field subset.
- Fixed a real-article readiness bound in the local PDF path: the document wait was 40 polls of 50ms, so a paper whose reader attached its PDF later than two seconds was reported as "could not be read locally" while it was still loading normally. The wait is now twelve seconds and stays cancellable through the caller's signal.
- Removed the release-visible redundancy from the native Preferences pane: the sidebar hint paragraph is gone, the Models section no longer repeats itself, "Export preferences" and its whole code path (presenter method, host port, shared text builder, tests) were deleted, and deleting history in the pane no longer leaves the count, empty state, search results or status line disagreeing with the store.
- The development XPI also bundles the licenses of the five third-party packages actually compiled into `content/zchatgpt.js` (`linkify-it`, `mdurl`, `uc.micro`, `punycode.js`, `entities`); those and the native Preferences pane files are required artifacts, so `npm run verify:artifacts` fails if any is missing. Gate results, artifact digests and host evidence per build are recorded in `docs/progress.md`, not here.
- Hardened `.github/workflows/ci.yml` and `release.yml`: the toolchain is pinned via `.nvmrc` (24.11.0, `engines >=24 <25`) instead of a floating major, CI now packages and verifies the development XPI (`runtime-prepare` → `package:dev` → `verify:artifacts`) in addition to `typecheck`/`lint`/`test:unit`, and no workflow uploads, publishes or tags anything. GUI Zotero host checks and `--live` model checks are explicitly excluded from CI.
- Bumped the bundled Codex runtime from `0.144.1` to the signed `rust-v0.154.0` darwin/arm64 release (new archive and binary SHA-256/size in `runtime/manifest.ts`), refreshed the one changed dependency license (`RATATUI-LICENSE`), moved both `packages/core/src/index.ts` version literals, and realigned the reader policy's two 0.154.0 defaults (`chatgpt_base_url`, removed `experimental_thread_config_endpoint`). The pinned fallback catalog now mirrors the embedded 0.154.0 set (11 ids, new visible default `gpt-6-astra`, daybreak ids, sol/terra/luna fallback window 372000 → 272000). Code/unit evidence only: packaging is deferred to one clean-tree build after all concurrent work lands, and whether a real signed-in account receives any new model remains unverified.

- Repository housekeeping (2026-09-15, no user-visible behaviour change): removed the orphaned archive/restore write path that the sidebar and Preferences pane stopped offering (legacy `archivedAt` records are still read, listed and never rewritten); deleted exports, presenter wrappers, host ports, stylesheet rules and zh strings that no product surface reached; deleted the S1–S4 dedicated-host drivers that asserted on the removed context-pane UI (s5/s6/context/live-model remain, and `prepare-host-test.mjs` now refuses to run without an explicit stage); and folded the iteration logs into git history so `docs/progress.md` only carries current state, evidence boundaries and remaining work.

Known limits (not yet verified): the new native Preferences pane in a real Zotero Preferences window (sandbox load of the fragment and bundle, native theming, keyboard focus, concurrent store writes) and the citation click-to-highlight path in a real reader (Gecko highlight visual, real page coordinates) plus whether a live model actually quotes verbatim; the sidebar's removed global controls are intentional, the pane copy follows the stored UI language (host-verified in both zh and en) while its Chinese/dark-light visual and keyboard focus are not visually verified; isolated official ChatGPT login and live model answers, stop/uncertain resume in flight, the final 0.4 XPI's native host UI, native annotation/acquisition against a real library or network, live image generation, and signed/public download or upgrade acceptance. No GitHub Release exists for this version.
