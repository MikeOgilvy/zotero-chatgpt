# Zotero × Codex：选区解释与侧栏对话

状态：可行性核查与首版设计，尚未实现或运行插件。
日期：2026-09-08。

正式项目名为 **Zotero Codex Reader**（ZCR），仓库名 `zotero-codex-reader`。当前技术路线与 macOS Cursor + Codex 流程以[项目决策](project-decisions.md)为准：生产插件通过 Gecko 原生管道直连 Codex，Node 仅作开发工具。

模块职责见[模块设计](module-design.md)，执行顺序见[分阶段计划](superpowers/plans/2026-09-08-zcr-implementation-stages.md)；原[任务细则](superpowers/plans/2026-09-08-zotero-codex-reader.md)提供 T0–T12 的实现与验收参考。

用户已进一步确定[使用流程](zotero-codex-user-flow.md)：一个 GitHub 插件安装包、自动加载和启动后台、插件内发起 ChatGPT 官方登录、底部模型/速度/推理控制。此前要求用户手动启动连接层或配对的开发便利性假设已被替换。

## 目标与已确定选择

用户在 Zotero 阅读 PDF 时，选中一段文字即可请求解释，或把它作为引用加入问题；回答与后续对话显示在 Zotero 内部的侧边栏。

## 首版交互

1. 选区**上方**增加插件操作条，保留其下方原生高亮/下划线面板。点击 **More details / 详细解释** 立即将选区及出处发送给当前论文对话，展开侧栏并流式显示回答。
2. 增加 **Ask in sidechat / 在侧栏提问**：自动展开侧栏，把选区加入引用卡片并聚焦输入框，保留页码，允许移除或添加更多选区；用户输入问题后再发送。这个动作本身不启动模型请求。
3. 对话默认按 PDF 附件保存。切换论文时切换对应对话，返回后可以继续追问；提供新建对话和停止生成。
4. 引用卡片保留附件标识和定位信息，支持返回原文。第一版具体跳转精度需在真实 PDF 中验证。
5. 输入框底部提供模型、速度和推理强度选择，动态加载后端支持项；同一对话内修改设置从下一条消息生效，本轮设置在发送时固定。
6. PDF 阅读器右上角搜索按钮左侧增加原生风格的 Codex 侧栏开关，未选择文字也可打开。聊天侧栏采用 Zotero 字体、配色和控件风格，并停靠在真实布局中。
7. 展开、关闭、拖动侧栏或调整窗口时，PDF 按可用空间适配并保持当前阅读段落；明确保留用户主动缩放选择和原生右栏状态。

首版完成标准：可以在真实 Zotero PDF 中选中文字、获得侧栏解释、继续追问，并在切换论文后恢复正确对话。

## 技术方案

完整平台 XPI 自带 Zotero 扩展、TypeScript 核心和固定 Codex 可执行组件。Gecko Subprocess 直接管理 Codex 的私有 stdio，核心负责会话与文本增量；Node 仅用于构建/测试，不随产品发布。普通用户安装后走官方登录，原生封装与自动启动仍需真实环境验证。

核心与界面在模块上分开，ProcessPort/StoragePort 隔离原生能力；全局服务持有进程、取消、恢复和记录。关闭视图不关闭后台，无自建 HTTP 数据服务或配对；监督器只控制插件自有 Codex，官方 OAuth 回调仍由 Codex 管理。

在插件侧栏点击“使用 ChatGPT 登录”后，App Server 发起官方浏览器授权，完成后侧栏自动就绪。账户状态由经验证的插件专用 Codex 后台管理，重启恢复、过期重登。插件不需要自行读取、复制或维护账户令牌。

这是由 Codex 驱动的 Zotero 界面。首版对话由插件管理，不承诺与 Codex 桌面应用现有任务或 side chat 自动同步。

## 每次请求携带什么

- 选中文字：保持原文与数学符号，避免静默改写。
- 出处：论文标题、作者、年份、附件标识；DOI 在可用时附带。
- 定位：显示页码、内部页面索引以及可用的选区坐标。页码标签与页面索引分别保存。
- 已提供的上下文范围：明确是选区、附近文字还是整页，不能把局部输入表述为已经阅读整篇论文。

默认先发送选区和出处；附近段落的可靠提取作为原型核查项。对于公式或图表，后续加入局部截图，以免 PDF 文本抽取丢失结构。首版不需要先建立整个文献库的向量索引。

## 后台行为

- 每个附件映射到自己的会话标识，状态由附件标识而非标题区分。
- 恢复对话使用 App Server 的 `thread/resume`，发起问题使用 `turn/start`，监听回复增量及完成/失败事件。
- 同一对话生成时保持请求顺序；停止按钮取消当前生成。失败重试不静默重复提交已被服务端接收的问题。
- 阅读会话默认采用只读权限；界面仍需明确呈现服务端错误和可能出现的交互请求。
- 记录并检测 Codex 版本。App Server 及部分传输仍标为实验性接口，不能据此承诺长期不变。

## 已核实与待验证

本机应用信息显示 Zotero **9.0.6**；本机 CLI 输出显示 Codex **0.144.1**，提供 `app-server`、协议 schema 生成功能及标准输入输出传输。

Zotero 官方文档介绍了 `renderTextSelectionPopup` 选区事件，以及 `Zotero.ItemPaneManager.registerSection` 自定义右侧面板区域。这些 API 的文档起源于 Zotero 7；Zotero 9 官方说明没有重大开发接口变化。本次只读核查也确认安装包 `omni.ja` 中仍存在上述接口。布局、生命周期和端到端行为仍需在原型中验证。

安装包源码核查显示，选区对象提供 `text`、`pageLabel`、`position.pageIndex` 和 `position.rects`，读取器提供附件 `itemID`。跨页选区存在处理范围限制，详细计划将 v0.1 收紧为单页文字选区，跨页提取放到后续验证，不能承诺任意多页选区完整发送。

Codex 官方文档明确支持在自定义客户端中使用认证、会话历史与流式事件。这支持本方案的后台选择，但不能替代端到端实测。

首轮验证范围：

1. 文本型 PDF 的选区文字、页码和附件归属是否准确。
2. 点击“加入侧栏对话”是否只添加引用；点击“详细解释”是否恰好发起一次请求。
3. 回复能否逐步显示、取消并继续追问。
4. 切换两个 PDF 后，会话和引用是否保持正确归属。
5. Zotero 重启或自有 Codex 进程退出后，能否显示清晰状态并恢复已有会话。
6. 无系统 Node/CLI 的环境是否可以只安装 XPI、点击登录后使用；同会话下一轮切模型/速度/推理是否正确。
7. 工具栏搜索旁的按钮、深浅主题与侧栏布局是否自然一致；开关/拖宽是否让 PDF 真正适配，阅读位置及标注坐标是否正确。
8. 选区上方插件按钮与原生标注面板是否共存，视口边缘是否正确避让；点击和展开侧栏后引用是否仍是原选区。
