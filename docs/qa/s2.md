## Isolated runtime probes (no login, no model call)

The pinned binary was launched outside Zotero with the plugin's exact launch arguments, environment allowlist and a fresh throwaway `CODEX_HOME` under `/tmp`, sending only `initialize`, `initialized`, `config/read`, `account/read`, `model/list` and `thread/start`:

- `--strict-config` plus every pinned `-c` value is accepted; the effective configuration echoes them. `tools.experimental_request_user_input.enabled` is accepted but not echoed, so the gate does not require it.
- Layers are one `sessionFlags` layer, an empty `user` layer at `${codexHome}/config.toml`, and an empty `system` layer for `/etc/codex/config.toml`; all origins are `sessionFlags`. `codexHome` is reported canonicalized (`/tmp` → `/private/tmp`).
- `thread/start` echoes a requested `null` service tier as `"default"` and an explicit tier verbatim; the earlier strict `null` comparison was the cause of all 16 failed attempts recorded in the previous session (“no turn was submitted”).
- `model/list` and `thread/start` work without an account; only `turn/start` needs the ChatGPT login.

## Regressions resolved

- `validateThread` compared the echoed service tier against the catalog default `null`; the pinned server reports `"default"`. The check now names the differing field and the request record carries that reason.
- `createS2Client` returned a usable client without inspecting the effective configuration. It now requests `config/read` with layers, rejects weakened values, enabled feature flags, non-empty managed/project layers, foreign user files and non-`sessionFlags` origins, and terminates the runtime on rejection. Global `approval_policy`, `sandbox_mode`, `default_permissions`, `approvals_reviewer`, `history.persistence = "none"`, `features.memories`/`remote_control` and `--strict-config` were added after being verified against the binary.
- Notification overflow, a blocked stdin write during close, and a pending login during close each left the client unable to settle; they are latched, raced against transport failure and cancelled respectively, with regressions.
- The supervisor dropped ownership of a process whose termination failed and could spawn a second runtime; ownership is now retained until exit is confirmed, retries terminate instead of spawning, and stage failures show constant text (`RuntimeFailure`) while other errors stay generic.
- A corrupt cached runtime binary produced a “reinstall” message that could not fix the profile cache; the corrupt file is now moved aside as evidence and the packaged copy is extracted again.
- Typed upstream errors (`codexErrorInfo`) map to constant user-facing reasons; the free-text upstream message is never stored.
- The S2 driver waited on a stale terminal state from a restored earlier request and held a reader reference that died when its tab was closed during a run; it now waits for a new request ID, resolves the reader by tab and closes leftover restored tabs first.

## Boundaries and next stage

This remains a **development preview**. The sidebar runs only the fixed synthetic question; selection actions, paper conversations, model/speed/reasoning controls and history are S3/S4 work. The official login click-through (`node scripts/prepare-host-test.mjs --s2 --login`) was not driven in this run because the profile was already signed in; login cancel/timeout states are covered by unit tests only. Extraction was verified from a profile path without spaces or non-ASCII characters. Process-crash recovery of the journal is host-tested through disable/re-enable; power-loss durability, download-origin quarantine/Gatekeeper behavior and the complete A01–A30 matrix remain S5/S6 work.

Reproduction commands are in [development.md](../development.md). Leave the dedicated Zotero window untouched while a host run is in progress; closing its reader tab aborts the run.
