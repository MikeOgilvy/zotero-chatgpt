# Zotero Codex Reader：用户流程

2026-09-08，依据用户对首版使用流程的明确说明修订。本文件是产品验收依据，优先于先前计划中的开发便利性假设；所述功能目前仍待实现。

## 1. 下载、安装和首次登录

1. 用户在 GitHub Release 下载适合自己平台的一个 Zotero 插件安装文件。
2. 打开 Zotero，通过插件管理器安装；插件自动加载。
3. 插件自动准备并启动随包提供的运行组件。必要时显示“正在准备”，用户无需安装 Node/Codex CLI、打开终端或复制本机配对码。
4. 首次打开聊天侧栏时显示 **使用 ChatGPT 登录**。
5. 点击后打开系统浏览器中的官方授权页；用户在官方页面完成登录。
6. 授权完成后，Zotero 侧栏自动显示已登录状态和可用的聊天设置。
7. 之后重启 Zotero 自动恢复可用登录；登录过期时在侧栏重新授权，保留文献与聊天历史。

运行组件由插件管理。确定的技术路线是 Gecko 原生 stdio 直连自带 Codex，Node 仅供构建/测试；普通用户不接触进程通信。项目名称和 macOS Cursor + Codex 流程见[项目决策](project-decisions.md)。

## 2. 工具栏入口和选区操作

在用户截图所示的 **PDF 阅读器右上角、搜索按钮左侧** 增加 Codex 侧栏开关，保留原来的搜索与 Zotero 侧栏按钮及相对顺序。这里是阅读器工具栏，不新增 macOS 顶部系统菜单项。

- 使用与相邻原生按钮一致的单色图标、尺寸、线宽、间距、hover/pressed 和键盘焦点样式；悬停提示“显示 Codex 侧栏 / 隐藏 Codex 侧栏”。
- 再次点击关闭聊天侧栏；按钮选中状态与实际聊天区域可见状态同步。
- 未选中文字时也可打开，直接查看当前 PDF 的历史或提问；未登录时显示登录入口。
- 工具栏开关只改变界面，不发送问题，不要求先创建标注。关闭侧栏保留草稿与正在生成的回答，重新打开可继续查看。

工具栏局部顺序：`…… [Codex 侧栏] [搜索] [Zotero 原生侧栏]`。精确宿主插入位置要在 T0/T2 验证；不能把落在工具栏另一端的按钮算作位置验收通过。

选中 PDF 中的一段文字，**选区上方**出现紧凑的插件操作条，原生高亮/下划线面板继续在下方工作：

```text
       [ More details | Ask in sidechat ]

            被选中的论文文字

        [ Zotero 原生颜色与划线面板 ]
```

上方操作条采用 Zotero 原生风格，两项横向排列；保持下方原生颜色、标注类型和点击行为。原生标注面板被宿主自动翻到上方时，插件操作条避开它。视口边缘空间不足时，按可见区域调整位置，不能把按钮裁出窗口或遮住原生操作。

点击插件操作前保存本次选区和出处快照，避免按钮点击、失焦或展开侧栏让引用丢失。移动鼠标到操作条能直接点击；重新选区、清除选区或切换 PDF 后旧操作条同步更新/关闭，不发送过期选区。

| 选项 | 点击后的行为 |
| --- | --- |
| **More details** | 自动展开右侧聊天窗口，以该段原文和出处发起详细解释，流式显示回答 |
| **Ask in sidechat** | 自动展开右侧聊天窗口，将原文放入引用卡，并聚焦问题输入框；用户输入问题后发送 |

这两个按钮共用同一个聊天界面和当前 PDF 的对话。More details 默认相当于替用户填入“请详细解释这段内容”；Ask in sidechat 让用户自行决定问题。

未登录时先保存选区并展示登录入口；登录完成后恢复引用和原动作。只有原动作是 More details 时才继续它尚未提交的那一次解释，登录回调重复到达不得产生重复请求；Ask 始终等待用户发送。

## 3. 侧栏布局

```text
┌──────────────────────────────┐
│ 当前论文 · 对话历史   新对话   │
├──────────────────────────────┤
│  引用：选中的原文              │
│  论文标题 · 第 4 页 · 返回原文  │
│                              │
│  用户的问题                   │
│  GPT 的回答                   │
│  后续追问与回答               │
│                              │
├──────────────────────────────┤
│ 待发送引用卡（可移除）         │
│ 输入问题……                   │
│                              │
│ 模型 ▾  速度 ▾  推理强度 ▾    │
│                     发送 / 停止│
└──────────────────────────────┘
```

聊天操作与设置能力向 Codex 对齐，视觉使用 Zotero 的界面语言：系统字体、字号层级、灰阶背景、分隔线、输入框、下拉菜单、滚动条和焦点状态。默认不使用醒目的品牌大按钮、厚阴影或独立网页式卡片布局。侧栏由插件实现，会话与推理由 Codex 后台提供。

### 停靠、宽度与原生侧栏协作

- 聊天区停靠在阅读器右侧并参与实际布局；展开后 PDF 视口变窄，关闭后视口恢复，不把聊天窗口悬浮盖在论文上。
- 优先使用 Zotero 原生右侧区域和分隔条；聊天入口定位到聊天区域，搜索、注释、文献信息等原生功能仍可使用，不叠加两个相互挤压的右侧栏。
- 分隔条可拖动，记住用户选择的宽度；窄窗口自动限制侧栏占比，底部设置控件换行/收紧，保留论文可见空间。
- 用户先前打开原生信息/笔记区域时，记录进入聊天前的侧栏状态；关闭聊天恢复该状态。若用户期间主动切换了原生区域，以用户最新操作为准，不强行恢复过时状态。
- 打开后焦点进入合适的聊天输入区；关闭后返回原工具栏按钮或阅读区域。搜索快捷键、PDF 翻页、选区和标注操作保持原生行为。

### PDF 自动适配与阅读位置

- 默认展开聊天时，论文按剩余阅读区域的宽度适配；拖动分隔条、调整窗口尺寸或关闭侧栏时重新计算。
- 保持当前页以及正在阅读的段落在相近屏幕位置。变化前后按 PDF 内的位置保存和恢复阅读锚点，不能只保存缩放前的 scrollTop，也不能关闭侧栏就跳回最初打开它的那一页。
- 原先为“适应宽度/适应整页/自动”时维持相应原生模式；原先为固定缩放时，打开侧栏暂时适配并记住原设置，关闭后恢复。
- 用户在侧栏打开期间主动调过缩放，之后以新选择为准；插件不在每次窗口变化时强行覆盖。关闭仍保留当前阅读段落，不恢复旧阅读页。
- 页面缩放必须通过阅读器实际布局和 PDF 渲染完成，不能给整个 PDF 容器加 CSS transform 冒充适配，导致文字选择/标注坐标错位。
- 开关过程避免空白闪烁和反复缩放，流式回答不触发 PDF 重新缩放。减少动态效果偏好开启时不使用侧栏滑动动画。

## 4. 模型、速度和推理强度

- **模型**：加载 Codex 返回的模型目录，展示名称和当前选择，不维护一张容易过期的硬编码菜单。
- **速度**：对应模型支持的 service tier；有多个档位时提供选择，没有额外档位时显示默认或不可选说明。
- **推理强度**：展示所选模型支持的 reasoning effort；它与速度是独立控制，不用降低推理强度来伪装速度切换。
- **切换规则**：可在同一对话中修改，下一次发送使用新设置并保留此前上下文，不强迫用户新建对话。
- **生成中的设置**：本次请求的设置在发送时固定；生成过程中改动只改变下一条消息，不重启或改写正在进行的回答。
- **不兼容组合**：切模型后重新核对速度和推理选项；若旧档位不支持，清楚显示新默认/待选择状态，发送前展示最终组合。
- **实际可用性**：目录中的项目不等于账户一定有额度；请求被拒绝时说明原因，不静默改模型、速度或计费档位。

开发基线 CLI 0.144.1 的 schema 已确认 `model/list` 包含 `supportedReasoningEfforts`、`serviceTiers` 和默认值，`turn/start` 支持 `model`、`serviceTier`、`effort` 覆盖；真实账户可用性和组合行为需实际验收。

## 5. 后续聊天

用户可继续提问、追加新的选区引用、复制回答、停止生成、查看历史或新建对话。继续提问沿用当前上下文；切换 PDF 时呈现对应附件的对话，返回后恢复记录和未发送内容。

首版明确对齐登录、选区问答、连续对话、模型/速度/推理控制、流式输出和停止。用户所说的“等等”形成可扩展的聊天设置区；未明确提出的 Codex 项目管理、电脑操作或所有工作区功能，不自动纳入这个阅读插件的首版范围。

## 6. 新的发布门槛

- 在没有系统 Node、没有系统 Codex CLI、没有开发目录的测试环境，完成下载一个 XPI → 安装 → 登录 → 提问。
- 插件自行管理后台进程，关闭侧栏不终止回答；退出 Zotero 或禁用插件时按生命周期正确收尾，重开可恢复。
- 浏览器授权成功、取消、失败、过期重登均有明确结果，不让用户靠终端排错。
- 同一对话切换模型、速度和推理强度，下一条请求设置正确且历史不丢。
- 工具栏按钮位置、原生视觉、侧栏开关与拖宽、PDF 自动适配和阅读锚点保持，都属于首版验收；具体用例 A25–A28，不能只检查按钮是否出现。
- 上方插件操作条和下方原生标注面板共存、视口边缘避让、点击不丢选区均需验收，见 A29–A30。
- 单一安装包的原生运行组件提取、执行、平台签名/隔离属性和升级回退必须实测；在它们通过前不能宣称上述安装体验已经实现。
