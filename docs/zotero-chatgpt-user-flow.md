# Zotero ChatGPT 产品行为与验收

本文件是当前产品行为的权威说明。实现机制见 [module-design](module-design.md)，开发与宿主命令见 [development](development.md)，已取得和仍缺少的证据见 [progress](progress.md)。这里的要求不是完成声明。

## 产品边界

Zotero ChatGPT 位于 Zotero Reader 侧栏，提供两个由用户显式选择的平级模式：

- **Chat** 承载官方 `chatgpt.com` 页面。登录、模型、远端对话、流式、停止和远端历史由该页面拥有；插件不能借 Codex 代答，也不能写 Zotero 文献库。
- **Agent** 通过随包 Codex App Server 对话，并可进入受控的 Zotero 原生任务：高亮、标签、集合成员关系、文献获取等。模型不能直接写库，只能产生受限候选；宿主程序校验、预览、批准、执行、读回并记账。

默认进入 Chat。复杂问题、长 PDF、Chat 失败或 Agent 已登录都不能让一次 Chat 请求自动改走 Agent。切换模式保留本地草稿和可见上下文，但两种服务维护各自的远端会话标识与历史，不能声称官方 ChatGPT 对话和 Codex 线程天然共享远端历史。

当前 PDF 是两种模式的默认阅读对象。每次发送冻结附件、profile、library、PDF 版本、问题、选区、设置、模式和已授权来源；之后切换标签或编辑草稿不能改变在途请求。首次外发前说明数据去向，并提供关闭自动 PDF 文本的入口。插件不后台上传整个文献库。

## Chat：官方页面上的当前论文问答

Chat 档显示官方 ChatGPT 页面。目标发送链路是：用户在官方可见输入框提交问题时，受限页面 actor 拦截该次可见提交 → 父进程冻结当前 PDF 文本、覆盖范围和最近选区 → actor 把带随机请求标记的上下文与问题写回同一个官方输入框并提交 → 只确认这个标记是否被页面接受。桥只匹配严格的 `https://chatgpt.com`，拒绝相似域名、凭据 URL、异常端口和其它 frame；它不读取回答正文、cookie、token 或认证文件。

选区上的 **More details** 在 Chat 档通过同一官方页面入口提交冻结选区；**Ask in sidechat** 只把冻结选区放入官方输入框，等待用户发送。它们不能调用原生 presenter 的 Agent 快捷路径。若 actor 或页面结构不可用，界面必须明确失败，不能退回剪贴板成功文案或偷偷启动 Codex。

Chat 的远端会话由官方页面拥有。插件最多为一个本地附件/聊天绑定经过规范化的官方 `/c/<id>` URL，不保存远端 transcript，也不把查询串、fragment、share URL 或其它 origin 当作会话身份。新建 Chat 与新建 Agent 各自创建对应服务的会话，不伪造跨服务统一历史。

以下完整链路只有真实宿主和真实服务证据才算通过：官方登录可完成；真实问题得到回复；流式、停止、历史和重启恢复可用；随机唯一合成 PDF 内容确实进入同一次官方对话。页面可见、本地 PDF 提取成功、actor 单元测试或 mock 回答均不能替代它。

## Agent：当前论文原生高亮

用户可直接说“高亮当前论文最重要的 5 处内容，并简要说明原因”，无需先选择 `/skill`。Agent 将该请求冻结为内置 annotate workflow，并把当前 PDF 的冻结文本交给真实 Codex 轮次。模型只返回严格 JSON：逐项给出原文 quote、零基物理页提示和原因；它不能选择 Zotero key、坐标或写入状态。

程序在冻结 PDF 版本上做全 PDF 唯一匹配。模型页码只是提示，不能隐藏同文档中的重复文本；不存在、重复、超过可靠搜索范围或几何不可靠的候选不写入。可靠候选转换为 Zotero 原生行矩形，允许跨行和相邻两页；跳回原文时把两页矩形一次性交给原生 Reader，不能改变当前缩放或旋转。

候选先进入 review。只有用户批准的项才由 `Annotations.saveFromJSON` 写入正确附件；写后必须按保留 key 读回精确快照。相同 model request 恢复时复用原任务；不同 request 对同一冻结位置也不能重复创建仍存在或结果不明的标注。停止只停止后续工作，不冒充已自动撤回先前成功项。

撤销仅删除账本中仍与写后快照完全一致的标注。人工后来修改的文字、颜色、标签或其它字段必须保留并报告 conflict。不确定写入先按保留 key 对账，不能盲目重试。

## Agent：整理当前 Zotero 选中文献

用户可直接说“按主题打标签，并归入合适的集合”。发送或排队点击当下，插件从**绑定的 Zotero 主窗口 library items view** 读取实际选中的普通条目；不把当前 Reader 的父条目、其它窗口或稍后的焦点变化当作选择。所有条目身份在第一次异步读回前复制，最多 50 项，且必须来自同一 library。

同一时刻冻结该 library 已存在且可编辑的集合。模型只看到 `itemIndex`、有限书目信息、已有标签、已有集合索引，以及 `collectionIndex + name`；看不到 item key、collection key、时间戳或完整 native signature。模型只能提出新增标签和新增集合成员关系，不能创建集合、删除/替换已有标签、移动条目、删除/合并文献或操作附件。

程序把索引映射回冻结快照并显示一次 review。批准后，在 Zotero transaction 内逐条核对条目仍等于预览快照、条目和集合仍可编辑，再做加法写入；随后读回标签、集合和非整理字段。任务只记录实际新增的值。相同 request 重放复用任务；若选择或候选内容改变则拒绝冲突重放。

撤销只移除本任务实际新增且仍属于写后精确快照的标签和集合关系。任何后续人工编辑都会让该项进入 conflict 并保持原样。若提交可能成功但写后快照未持久化，结果保持 uncertain；当前恰好出现相同标签或集合不能被追认为任务所有。

## Agent：获取文献

获取只接受明确 DOI 或公开文章 URL 和明确目标集合：未保存元数据预览 → DOI 查重 → review → 创建新条目或给已有条目新增集合关系 → 可选尝试合法 OA PDF。批准的元数据使用固定字段白名单，不携带 notes、tags、relations、本地路径或执行权限。

下载逐跳拒绝私网/本地地址，检查 PDF 类型、首页标题/DOI、补充材料标志、页数和哈希。无法确认时保留正确元数据并报告 unavailable/uncertain，不绕过登录或访问控制，不把解析器的版本标签冒充独立鉴定。

## 会话、队列与恢复

每条本地消息记录实际 `mode`。`requestId` 与冻结输入哈希共同去重；不同内容复用同一 ID 必须拒绝。发送先原子保存用户消息与 accepted 状态，随后才允许外发。queued 请求保存完整快照，排队期间切模式、切选择或改设置不能改变它。

Chat 恢复只读本地显示状态，不能启动 Codex、恢复 Codex thread 或加载原生任务。只有用户进入 Agent 后才允许启动随包运行时、恢复 Agent 请求并加载动作账本。dispatching/running 的 Agent 请求在进程中断后为 uncertain，先用上游历史对账；不能自动重发。删除聊天不等于撤销原生输出。

ChatGPT 远端历史、Codex 线程、本地会话、草稿、PDF 缓存、原生任务账本和账户目录有独立寿命。退出登录、清缓存、删除聊天或卸载不能被当成另一类数据的删除。

## 阅读与交互约束

- PDF 缩放与聊天字号独立；打开/关闭侧栏、流式更新和原文跳转保持阅读锚点、焦点和用户缩放。
- 中文 IME 组合期间 Enter 不发送。发送、停止、排队、重试、复制、新建、批准、对账和撤销都必须对应真实状态。
- 长文档不静默截断后声称全文已读。扫描页、提取失败、未提供图像、预算未知、聚焦范围和多轮阅读分别显示实际覆盖。
- 正文、网页、模型输出、第三方 skill 和 PDF 内指令都是数据，不能授予权限。导入 skill 不自动启用脚本、MCP、依赖或额外工具。
- 诊断不含正文、图像、凭据、cookie、token、认证目录或私人路径。普通日志只允许版本、阶段和错误码等白名单字段。

## 验收证据边界

自动测试、工作树宿主驱动、真实 ChatGPT/Codex 服务和最终 XPI 是四层不同证据。状态只使用：

- **PASS**：该层本次确实执行并满足断言。
- **FAIL**：该层本次执行但未满足断言，失败报告必须保留。
- **BLOCKED**：平台或必要人工登录阻止抵达目标边界。
- **NOT RUN**：本次没有执行。

核心验收至少分别覆盖：Chat 不启动 Codex；官方页面真实提交含随机 PDF token；Agent 高亮从真实模型候选到原生保存/重开/跳转/撤销；真实 library 选择到标签/集合读回/冲突撤销；停止、超时、重试和进程中断无重复写入；最终 XPI 在干净隔离 profile 无 Node 运行依赖。当前结论见 [progress](progress.md)。
