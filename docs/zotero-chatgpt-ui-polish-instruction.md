## 2. 单行共同工具栏

### 2.1 固定结构

正常态采用以下顺序，Chat、Agent 和打开 History 时都使用同一工具栏：

```text
[ Chat | Agent ]  会话短标题…   [复制文献信息] [复制 PDF]  [新建] [历史] [更多（按需）]
────────────────────────────────────────────────────────────────────────────
模式内容区或 History 内容区
```

方括号内中文仅表示控件语义，实际复制控件为图标按钮。保留已有、真正接线的新建与历史导航；“只保留两个功能”指文献快捷动作，不是删除模式切换、新建、历史或必要的设置入口。

两个复制动作始终以当前 Reader 的 PDF/父书目条目为来源，不因 History 正在显示另一篇论文的记录，就改成复制那一行文献。两种模式中位置、顺序和语义一致；无需登录或连接 Agent。

会话标题与当前论文是不同身份。标题继续遵循已有会话逻辑，不为省空间强行改成论文名，不把历史记录标题当作复制来源。无自定义标题的新 Agent 使用 `New agent`；只修默认标题生成/展示，不覆盖用户已经命名为 `New chat` 的旧记录。

### 2.2 尺寸与排版

以下是本轮设计目标，以实际 CSS px 测量，不从截图物理像素倒推：

| 项目 | 目标 |
| --- | --- |
| 正常态共同头部总高度 | 约 40–44 CSS px；默认字号、常规侧栏尽量不超过 48 CSS px |
| 左右内边距 | 8–12 CSS px，同一头部内对齐 |
| 图标绘制尺寸 | 统一 16–18 CSS px，选择一套基准 |
| 图标按钮命中区 | 约 32 × 32 CSS px，不为压缩空间缩成难点的小图标 |
| 同组按钮间距 | 2–4 CSS px；组间约 8 CSS px |
| 会话标题 | 系统 UI 字体，约 13 CSS px，适度字重，单行省略 |
| 下边界 | 一条细分隔线，不叠加每个旧容器的边线 |

保持既有整体配色与视觉语言，只统一明显不一致的间距、字重、圆角、边线和图标。不要新增渐变、大阴影、大标题或大卡片。

### 2.3 窄窗优先级

先收缩会话标题，再隐藏重复标题；不要先移动模式开关、缩小命中区或把两个复制按钮挤到第二行。再不足时，把次要导航收入已有或确有必要的更多菜单。常规测试宽度下，两个复制动作直接可达。

极窄窗或放大字号下，以所有必要操作可达为先；确实放不下可进入明确的溢出菜单或必要重排，不能硬裁切。正常宽度不因标题长而增加一整行。工具栏自身不得形成水平滚动条。

### 2.4 彻底移除正常态遗留区

从默认可见结构中移除：

- `Current PDF · all … pages read locally` 整行，包括箭头、额外 padding、min-height、空 wrapper 和重复边线。
- 下方 `Copy paper context` / `Copy PDF file` 的大文字按钮；它们移到顶部图标区，不保留第二套。
- 顶部/下方文献工具区的 `Copy selection` 与常驻刷新按钮。
- 常驻 `Continue with current PDF`。
- 常驻的“将加入上下文”“已接受”“已复制若干页”等流水提示。

不是把旧面板默认折叠一下就算完成。核对旧展开状态/偏好是否会使它下次重新出现；只迁移必要的展示状态，不清空自动 PDF 开关或其它用户设置。清理失去消费者的视图代码、选择器与文案，但保留其它入口实际使用的能力。

移除工具栏 `Copy selection` 不等于删除 Reader 自带复制或 `Ask in sidechat` / `More details`；这些既有选区能力继续按原路由工作。

### 2.5 去掉常驻行，不隐瞒上下文事实

自动 PDF 上下文仍存在。其开关、当前来源、实际待发范围、限制和异常详情，收进更多菜单中的 `Paper & context details` 或仓库已有等价入口。没有合适入口时，只新增一个必要的更多菜单，不另造常驻状态行。

详情将“待发送的 PDF 文本范围”和“手动复制的书目信息”分开说明。提取了 19 页不代表发送了 19 页，更不代表模型已经读完。移除状态行不能改变原有输入预算、冻结快照、首次外发告知或自动附带开关。

正常态不显示成功横幅。需要用户处理的上下文错误或来源冲突，使用工具栏内不改变高度的可发现状态提示和可打开的详情；首次告知、明确冲突或用户主动展开的面板可临时占空间，但不能伪装正常完成、静默丢上下文或自动重发问题。

若旧 `Continue…` 承担真实的来源选择，把它迁到有明确文案的冲突详情中，只影响下一次输入；不能直接删掉安全判断，也不能继续作为所有请求的固定步骤。

## 3. 两个图标按钮：必须能辨认、能理解、能可靠操作

### 3.1 图标与文案

| 动作 | 图标方向 | Tooltip 标题 / accessible name | Tooltip 说明 |
| --- | --- | --- | --- |
| 复制书目信息 | 剪贴板带文字横线；不能只是含义不清的方框 | `Copy paper context` | `Copy title, authors, publication, year, DOI and abstract as text. Does not include PDF full text.` |
| 复制文件 | 折角文件图标，使用可清楚识别的 PDF 标识或既有 PDF-file 图标 | `Copy PDF file` | `Copy the current PDF file to the clipboard. Paste it into ChatGPT to attach it.` |

英文是现有英文 UI 的基准，同步维护中文资源。中文可用“复制文献信息”“复制 PDF 文件”，说明与英文一致。直接完成复制的按钮名称不使用省略号；只有真正打开后续选择步骤才需要表达后续操作。

优先复用已安装的图标体系；必要时增加少量本地 SVG，不引入外部图标 CDN、字体图标包或新的 UI 框架。两个动作不能使用完全一样的图标。新建用加号，历史用历史/时钟，菜单用省略号，关闭用叉号；不串用语义。

对复制图标要检查真实渲染：SVG namespace、viewBox、路径是否裁切、fill/stroke 是否被全局样式覆盖、深浅主题颜色、不同缩放下清晰度及视觉居中。不能只换一个 icon 字符串就宣布修复。采用统一线宽与 `currentColor`；小图标不能挤进难以辨认的多重角标。

### 3.2 Hover、键盘和反馈

使用真正的按钮语义和本地化 accessible name。Tooltip 鼠标悬停约 300–500 ms 后出现，键盘聚焦时也可读取说明；不只靠鼠标，也不同时弹两个重复提示。说明中可提供当前来源短标题，不能把完整摘要塞进 Tooltip。

Tooltip 与菜单不得改变工具栏高度、被容器裁切或覆盖到无法操作的 browser 层。利用已有宿主/浮层能力，无法跨层覆盖时采用安全的插件内替代，不修改宿主安全策略。

按钮应有一致的 default、hover、pressed、focus-visible、disabled；仅在真实异步操作中显示 busy。成功后原位置短暂显示 check/`Copied`，约 1–2 秒恢复，宽高与相邻布局不变，并通过合适的 live region 反馈。文件复制可提示 `PDF copied — paste to attach`，但不永久占据一行。

失败必须有可再次查看的简短原因和可重试动作，不显示成功 check。连续复制不堆积通知。禁用时说明是“没有书目信息”还是“本地 PDF 不可用”；原因应能通过键盘/辅助技术发现。若用 aria-disabled，必须同时阻止点击与键盘执行，不能只把颜色变灰。

复制只写剪贴板，不自动粘贴、不发送 Chat 消息、不切模式、不上传文件、不启动模型，也不因悬停/聚焦执行复制。

## 4. `Copy paper context` 的新内容契约

### 4.1 只复制真实、必要的本地文献信息

默认字段顺序：

```text
Title: …
Authors: …
Publication: …
Year: …
DOI: …

Abstract:
…
```

这里的省略号表示已有字段值，不是要复制的占位内容。实际输出是可直接粘贴的纯文本，不包代码围栏、不输出 JSON、不额外加系统指令或聊天问题。

字段只来自当前附件对应的本地 Zotero 书目元数据。对于不同条目类型，用真实的期刊、会议录、书籍或预印本载体信息作为 Publication；没有就省略，不能把所有文献都伪装成 journal article。

| 字段 | 规则 |
| --- | --- |
| Title | 使用书目标题，不使用会话标题、插件名称或附件 UUID |
| Authors | 保留本地作者顺序、个人姓名及机构作者语义；不把 editor 强当 author，不无故变成 et al. |
| Publication | 使用该条目确实存在的发表载体；不新增推测的期刊/出版社信息 |
| Year | 只从可可靠解析的本地日期取得；不能填当前年份 |
| DOI | 有就复制一个规范化标识；去除已知 resolver 前缀或 `doi:` 标签及外围空白，但不破坏后缀或猜补内容 |
| Abstract | 原有摘要完整保留，做安全的纯文本清理；不是模型重新总结，也不是正文前几段 |
| URL（可选） | 仅无 DOI 且已有合适公开文献 URL 时补一行，不重复 DOI 链接；不包含本地路径、凭据或认证参数 |

缺失字段直接省略，不堆积 `N/A`、`Unknown` 或空标签。没有 abstract 就不创建 Abstract 段落；反馈/详情可以说明摘要缺失，但不能用生成摘要、正文截取、历史回答来补齐。

无父书目条目且没有可证明的书目信息时，说明“没有可复制的文献信息”，禁用该动作；有本地文件时 `Copy PDF file` 仍然可用。反过来，元数据存在但 PDF 未落地时，复制书目信息仍应可用。

不要联网补 DOI/abstract，不调用 Crossref、翻译器、Codex 或其它模型，不为了复制等待整篇 PDF 提取。此动作不修改 Zotero 条目。

### 4.2 文本清理和防混入

清理摘要/标题中的展示用 HTML 与多余空白，保留段落、Unicode、数学文本和有意义的换行。采用安全的惰性文本转换，不执行 HTML、脚本或加载外部资源；不要用粗暴规则误删数学符号。

明确禁止混入：

- PDF 正文、前两页、selection、引用列表或旧的 text brief。
- `Current PDF`、`19 pages read locally`、`2 of 19 pages; shortened`、请求 marker、内部 ID、缓存路径和调试信息。
- 会话历史、用户问题、Agent instructions、模型总结或额外的“请忽略之前指令”等提示词。
- 源条目没有提供的作者、期刊、年份、DOI、摘要内容。

### 4.3 与自动发送的 PDF 上下文彻底分开

**本轮只改变手动复制按钮的输出。不能因为复用了旧 formatter，就把 Chat/Agent 真正发送的 PDF 正文也一并换成 metadata + abstract。**

先检查旧 `copyPaperContext` 与发送路径是否共享组装函数；按实际依赖拆出必要的小型纯 formatter/调用边界，不复制整套 Context 系统。自动上下文仍使用已有的文档预算、正文/选区、覆盖说明和冻结机制。

关闭自动 PDF 上下文，不应禁用用户主动复制书目信息；手动复制也不能重新打开自动 PDF 开关。

### 4.4 来源和异步竞态

点击时固定当前 profile/library、attachment 和 parent item 身份。异步读取按固定 ID 进行，不能在回调里重新取“当前论文”，拼出 A 的标题与 B 的摘要。

在同一次本地数据快照中格式化全部字段。点击 A 后切换到 B，不得悄悄改成复制 B；若该次操作继续完成，反馈必须能表明复制的是 A。

两个复制动作共用必要的窄操作序列保护：后发的复制意图不能被先发、后完成的回调覆盖。只在即将写入系统剪贴板时提交当前仍有效的操作；关闭/卸载界面后不让失效回调写剪贴板或更新已销毁控件。不为此新增通用任务队列或框架。

## 5. `Copy PDF file`：复制文件，不是复制路径或上传

保留并验证宿主真实的文件剪贴板能力。应复制当前 PDF 的文件对象/受支持文件格式，使用户能在支持文件粘贴的目标中粘贴；不能把本地路径或 `file://…` 文本冒充 PDF 文件。

文件必须属于点击时冻结的附件。有本地文件才能复制；文件缺失、尚未同步或当前宿主不支持时明确解释，不自动下载、不触发同步、不打开登录或远程服务。

优先复用现有、安全的宿主剪贴板适配。源码与宿主检查确认其 API/格式实际可用，不能凭 Web 浏览器 Clipboard API 的假设替代 Zotero/Gecko 文件复制。

不修改或重命名用户原 PDF。确需临时副本时，用可读、安全、避免冲突的文件名，保留来源身份，且生命周期足以让用户稍后粘贴；不要点击后立即删除导致“复制成功但无法粘贴”。不要为美观无理由复制大文件或加入新的后台缓存机制。

复制成功不等于官网出现附件、上传完成或模型收到文件。不要显示 `Attached`、`Uploaded` 或“已发送全文”。本轮使用合成 PDF，在本地受控目标验证文件格式/粘贴即可，不要求向 ChatGPT 实际上传。

系统剪贴板是全局资源。测试只验证自己明确写入的合成内容，不先读取、记录或保存用户此前的剪贴板，也不启动循环监控。

## 6. History 删除同步：必须修复数据链路，不只删 DOM

### 6.1 先建立可复现证据

用合成会话在专用测试存储复现：侧栏打开 History，Preferences 打开同一范围的数据管理；在 Settings 删除一个已存在记录，观察持久化结果、计数和侧栏行是否同步变化。

沿实际实现追踪：

```text
Settings 删除意图
→ 删除/校验服务
→ 权威持久化与相关索引
→ 本地变更通知或失效机制
→ 各窗口的历史查询/缓存
→ Sidebar 列表、计数、当前选中会话与标签
```

区分“删除实际没有落盘”“删了另一范围/身份”“落盘但索引没更新”“UI 没订阅”“旧异步查询覆盖新状态”“活动 presenter 又保存回已删除记录”。记录实际找到的根因与相关代码，不凭旧计划认定必然是双写者。

### 6.2 最小修复原则

Settings 与 Sidebar 的删除必须经过同一个权威的本地会话删除入口，并保留当前的活动请求/任务依赖检查。复用现有存储所有者和事件机制；若缺少同步能力，只补必要的订阅/失效通知，不新增数据库、全局事件框架或第二套持久化系统。

删除按稳定会话 ID 和正确的 profile/library 范围处理，不按标题、DOI、列表位置或 parent item 模糊删除。同名记录、同一论文的多个对话、同一 parent 下多个附件不能被误删。

删除持久化成功后才向消费者传播“已删除”，同步刷新相关本地索引、查询缓存、分组、计数、选中项与已打开视图。优先使用提交后更新：删除中禁用该行重复操作，失败保留可见记录与原因。已有乐观删除必须完整处理失败恢复，不能只隐藏行。

同步是双向的：Settings 删除更新 Sidebar；Sidebar 删除也更新打开的 Settings。更新覆盖同一 profile 内相关的多窗口/多 Reader；其它 profile 不受影响。隐藏视图可先失效，但下次显示前必须拿到新状态。

不要用“删除后重启 Zotero”“切一下模式”“刷新官网”“每秒轮询文件”作为修复方案。已有打开/聚焦时重验可作为兜底，不能代替提交后的即时同步。

### 6.3 防止删除后复活

必须覆盖两种竞态：

1. **旧查询晚返回。** 删除前开始的 list/search 查询在删除后返回，不能把旧行重新插回 UI。使用现有版本/请求序列机制，或补最小的查询世代校验；同时校验范围、搜索词和 view 是否仍有效。
2. **旧保存晚执行。** 某 presenter 或防抖保存仍握着已删除对象，不能在下一次 render、切模式或卸载时重建同一记录。协调当前存储所有者的串行保存/删除和订阅失效，区分“显式新建”与“保存一个已不存在的旧记录”。不要仅靠 UI 隐藏列表项。

幂等重复删除、批量删除部分失败、索引更新失败都应有真实结果，不宣称全部成功。不得为这次修复随意更改持久化 schema/hash、重建所有用户记录或清空整个历史目录。

### 6.4 删除当前会话与数据寿命

- 删除非当前记录：当前模式、问题草稿、PDF 阅读位置、正在查看的其它会话不变。
- 删除当前闲置的 Agent 本地记录：清理失效选中项与 transcript 引用，进入当前模式的未保存空会话。未明确纳入删除范围的未发送草稿应保留为独立本地草稿，不为保留草稿重建被删记录，也不连接 Codex。
- 存在活动/排队/结果不确定的请求或任务：沿用安全依赖门禁，明确阻止不安全删除；不偷偷取消、撤销或丢失账本来让删除成功。
- 删除 Chat 本地绑定：删除的是插件的本地入口和绑定，不删除官网对话。清除本地选中/缓存引用，但不自动关闭或跳转官方页面、不丢官网输入草稿，也不把仍显示的旧官方对话冒称 `New chat`。
- 浏览器的旧 URL 通知、恢复或自动保存回调不得把刚删的同一个本地绑定立即建回来。只有后续明确的新建/保存意图才能按产品规则建立新的本地记录，不能后台复活旧 ID。
- 删除本地会话不等于撤销原生标注、删除条目/PDF、清认证、清全部草稿或删除上游 Codex thread。账本和数据类别保持各自寿命。

“清理缓存”与“删除历史记录”也不同；不能为了让数字一致，把无关缓存操作扩大为删除历史。

### 6.5 删除后的列表体验

保留搜索词、过滤条件和尽可能稳定的滚动锚点。删除行后焦点移到下一行、上一行或空态的合理入口，而不是丢到窗口根节点。空分组标题同步移除；删除最后一条记录显示真正空态，不留空白行、假计数或旧标题。

Settings 总计与 History 过滤结果可有不同统计范围；各自应基于同一权威数据正确计算，不直接复制一个数字到所有地方。

所有跨视图订阅、窗口监听和异步任务都要在卸载时解除/失效。多次开关侧栏和 Preferences 不应造成重复通知、重复删除或内存泄漏。

## 7. History 与相关图标的局部排版精修

保留现有历史信息结构，不重做整套导航。

| 元素 | 具体要求 |
| --- | --- |
| 搜索框 | 默认约 30–34 CSS px 高，紧凑内边距；使用单一清晰 focus ring，不叠加粗边框和巨大蓝色阴影 |
| 搜索文案 | 使用与实际范围一致的 `Search local history…` 或等价本地化；不暗示搜索官网全部 transcript |
| 分组标题 | 约 11–12 CSS px，统一上下间距，弱于会话标题；不要每组占大段空白 |
| 历史行 | 标题一行、论文/时间等次要信息一行；默认约 44–52 CSS px，放大字号自然增长 |
| 长标题与论文名 | 单行省略、详情可达，不挤出操作图标，不把一行撑成多行大卡片 |
| 当前选中记录 | 克制背景与正确选中语义；不要让每一行都带像“任务已完成”的圆形勾 |
| 来源 | 本地 Chat 绑定、Agent、来源未知的旧记录有准确标识；不凭旧 `mode: chat` 推断官网来源 |
| 行末动作 | 使用省略号菜单中的明确删除项，取代含义不清的常驻叉号；hover/focus 出现时预留空间，避免行跳动 |
| 标签关闭 | 叉号只表示关闭该本地视图/标签，不与删除历史混用 |

删除菜单文案说明实际范围，例如 `Delete local conversation…` / `Remove local Chat binding…`；沿用恰当的一次确认，说明不影响原始论文与官网历史。开发过程中无需我确认，不等于取消产品用户触发数据删除时的保护。不要增加没有真实恢复能力的“Undo”成功提示。

菜单项点击不能同时触发行选择或新建；使用正确事件边界。键盘可进入行末菜单，Escape 关闭并返回触发点，不关闭 PDF 或改官网状态。

时间分组按用户本地日历日计算，不用“过去 24 小时”冒充 Yesterday；基于真实活动时间排序。跨午夜/再次打开时重新计算，配合冻结时间和时区的测试，不硬编码截图日期，也不为此增加频繁轮询。

## 8. 验收矩阵：优先覆盖本轮真实故障

先建立能复现历史不同步和复制语义错误的回归，再实现。用实际交互、数据和端口结果断言，不以“源码里包含某个字符串”或“新增了通知函数”代替行为验证。

| ID | 必须验证的场景 | 合格结果 |
| --- | --- | --- |
| P-01 | Chat / Agent / History 默认头部 | 共同单行，无 Current PDF 行、遗留操作区、空占位；模式与复制位置稳定 |
| P-02 | 360 / 480 / 720 CSS px、长标题、放大字号 | 正常宽度紧凑；标题优先让位；极端情况必要操作仍可达，无遮挡/横向滚动 |
| P-03 | 两个复制图标的深浅主题、hover/focus/disabled/busy/success/error | 清晰、可区分、语义正确；Tooltip 可读，反馈不改变头部高度 |
| P-04 | 完整本地元数据 | 纯文本字段顺序稳定，作者/摘要完整，无 PDF 正文、选区、历史、内部状态 |
| P-05 | 无摘要/DOI、机构作者、非期刊条目、Unicode/格式化摘要 | 只输出存在的事实，不补造、不联网、不使用模型，清理不执行内容 |
| P-06 | 有元数据但文件缺失；无书目信息但有 PDF | 两个按钮独立可用性正确，不能一缺就全部禁用 |
| P-07 | 点击复制 A 后切 B；A/B 异步完成顺序颠倒 | 字段不串文献，旧复制不覆盖后一次明确意图，反馈来源正确 |
| P-08 | 手动复制与自动 PDF 开关/发送组装 | 手动内容变精简；原有自动正文、覆盖与冻结逻辑没有被替换或削弱 |
| P-09 | 本地 PDF 文件复制成功/失败/不支持 | 成功有真实文件格式；失败不冒充路径复制或上传；不改原文件 |
| H-01 | Settings 删除，Sidebar History 已打开 | 落盘后下一次正常 UI 更新即移除，无需刷新/切模式/重启；计数和分组一致 |
| H-02 | Sidebar 删除，Settings 已打开；相关多窗口 | 所有相关视图同步，其它 scope 不误删；隐藏视图再次打开无旧项 |
| H-03 | 删除失败、重复删除、批量部分失败 | 结果真实、失败可处理，不虚减计数或假装全部成功 |
| H-04 | 删除前旧 list/search 在删除后返回 | 已删除记录不会复活，搜索词/范围和焦点保持正确 |
| H-05 | 删除后旧 presenter/save/URL 通知到达 | 不重建旧记录或旧本地绑定；重开与重启后仍符合删除结果 |
| H-06 | 当前记录、非当前记录、最后一条、活动依赖 | 当前选择/空态/草稿处理正确；活动任务保护保留，不触发远端恢复或原生撤销 |
| H-07 | 同标题/同论文多个会话、多附件、多 profile | 仅准确 ID 和范围被删除，不按名字批量误删 |
| H-08 | 多次打开/关闭侧栏和 Preferences | 订阅无累积，销毁后的回调无写入/更新，菜单焦点与滚动稳定 |

构造一个含 `FULLTEXT_ONLY_SHOULD_NOT_COPY` 的合成 PDF 正文和一个不同的摘要，验证手动复制不含前者；另用既有发送组装测试确认自动 PDF 输入仍能包含该正文，防止两个路径被一起改小。测试不会实际发送模型请求。

删除同步至少做一条使用真实本地存储和两个独立视图适配器的离线集成回归；不能让两个 mock 共享同一个数组就宣称跨窗口同步已修。能运行 Zotero 时，再在合成 profile 中验证实际 Preferences 与 Sidebar 的桥接。

剪贴板单测只证明适配调用；真实文件复制成功需要宿主对自己写入的合成文件做验证。DOM mock 的固定矩形不算真实头部高度证明。

## 9. 执行顺序、质量门禁与交付
